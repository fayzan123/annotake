# Flipbook M0 Spikes Implementation Plan

> Written when the app was called Flipbook; it's Annotake since 2026-09-30 ([distribution design §3](2026-09-30-distribution-design.md#3-the-name-annotake)).

> **How to execute:** work through the tasks in order. Every task ends with manual checks that Fayzan runs at his Mac, so pause at each **Manual check** block for his results. Steps use checkbox (`- [ ]`) syntax for tracking. Don't use any superpowers skills to execute this plan.

**Goal:** Answer the risky questions in spec §10 M0 with throwaway code, and record the answers before any real app code depends on them.

**Architecture:** A throwaway menu-bar app, `FlipbookSpike`, lives in `spikes/` as its own SwiftPM package. It is bundled into a `.app` and signed with the same free self-signed identity the real app will use. Each task adds one experiment to its menu; Fayzan runs the checks and the results go into `docs/spikes/findings.md`. The signing and bundling scripts from Task 1 are *not* throwaway: the real app reuses them.

**Tech Stack:** Swift 6.2 (Command Line Tools 26.3), AppKit, ScreenCaptureKit, CoreGraphics event taps, ApplicationServices (Accessibility), GNU Make, `/usr/bin/openssl` (LibreSSL), `security`, `codesign`.

**Spec:** `docs/spec.md` (read §3.1, §3.4, §6.2, §7, §9, §10). Background facts and sources: `docs/research-notes.md`.

**Global Constraints** (inherited by every task):
- Spike code is throwaway. It lives only under `spikes/`, is never imported by the real app, and stays small: no abstractions and no tests.
- Build only on Fayzan's personal MacBook, which runs macOS 15.7. Work-Mac checks (macOS 26) use a zip of the built app.
- No network use and no AI anywhere in the app.
- The signing identity is named exactly `Flipbook Local Signing`. It lives in the keychain `.signing/flipbook-signing.keychain-db`, whose password is `flipbook-local`. `.signing/` is never committed.
- Bundle ids: `com.fayzanmalik.flipbook.spike` for the spike, and `com.fayzanmalik.flipbook` for the real app, which comes later. Using different ids keeps their macOS permission entries separate.
- Minimum macOS 15.0.
- Every commit message ends with the line `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- Record every observation, including failures, in `docs/spikes/findings.md` under the matching heading.

- [ ] **Step 3: Write `scripts/make-cert.sh`.** It must run under `/bin/bash` with `set -euo pipefail`, from the repo root. Use a config file rather than `-addext`, so that LibreSSL works:

```bash
#!/bin/bash
set -euo pipefail
cd "$(dirname "$0")/.."
DIR=.signing; NAME="Flipbook Local Signing"; PASS=flipbook-local
KC="$PWD/$DIR/flipbook-signing.keychain-db"
if [ -f "$KC" ] && security find-identity -p codesigning "$KC" | grep -q "$NAME"; then
  echo "Signing identity already exists"; exit 0
fi
mkdir -p "$DIR"
cat > "$DIR/cert.cnf" <<EOF
[req]
distinguished_name = dn
x509_extensions = ext
prompt = no
[dn]
CN = $NAME
[ext]
basicConstraints = critical, CA:false
keyUsage = critical, digitalSignature
extendedKeyUsage = critical, codeSigning
EOF
/usr/bin/openssl req -x509 -newkey rsa:2048 -nodes -days 3650 -config "$DIR/cert.cnf" \
  -keyout "$DIR/key.pem" -out "$DIR/cert.pem"
/usr/bin/openssl pkcs12 -export -inkey "$DIR/key.pem" -in "$DIR/cert.pem" \
  -out "$DIR/identity.p12" -passout "pass:$PASS"
security create-keychain -p "$PASS" "$KC"
security set-keychain-settings "$KC"
security unlock-keychain -p "$PASS" "$KC"
security import "$DIR/identity.p12" -k "$KC" -P "$PASS" -T /usr/bin/codesign
security set-key-partition-list -S apple-tool:,apple: -s -k "$PASS" "$KC" >/dev/null
security list-keychains -d user -s "$KC" $(security list-keychains -d user | tr -d '"')
rm -f "$DIR/key.pem" "$DIR/identity.p12"
security find-identity -p codesigning "$KC"
```

Pointer's `build.sh` (MIT, github.com/abhitsian/pointer) uses the same approach. Consult it if `codesign` rejects the identity.

- [ ] **Step 5: Write `scripts/bundle-app.sh`.**
  - Takes four arguments: `<executable> <AppName> <bundle-id> <out-dir>`.
  - Creates `<out-dir>/<AppName>.app/Contents/{MacOS,Resources}` and copies the executable to `Contents/MacOS/<AppName>`.
  - Writes `Contents/Info.plist` with these keys:

    | Key | Value |
    |---|---|
    | `CFBundleIdentifier` | the bundle-id argument |
    | `CFBundleName` | AppName |
    | `CFBundleExecutable` | AppName |
    | `CFBundlePackageType` | `APPL` |
    | `CFBundleShortVersionString` | `0.0.1` |
    | `CFBundleVersion` | `1` |
    | `LSMinimumSystemVersion` | `15.0` |
    | `LSUIElement` | `true` |
    | `NSHighResolutionCapable` | `true` |

  - Then runs:

    ```
    security unlock-keychain -p flipbook-local "$KC"
    codesign --force --options runtime --timestamp=none --keychain "$KC" --sign "Flipbook Local Signing" "$APP"
    codesign --verify --verbose=2 "$APP"
    ```

### Task 2: Spike A — Right ⌘ gestures, click cleanup, Esc, permissions

**Files:**
- Create: `spikes/Sources/FlipbookSpike/TriggerSpike.swift`
- Modify: `spikes/Sources/FlipbookSpike/main.swift` (add the `Trigger spike` menu item, which toggles the spike on and off)
- Modify: `docs/spikes/findings.md` (**Trigger & click cleanup**)

**Interfaces:**
- Consumes: `log(_:)` and `SpikeMenu` from Task 1.
- Produces: nothing reused. The real gesture logic is `GestureRecognizer` in the M1 plan.

**What to build (throwaway, minimal):**

**Permission probes.** At toggle-on, log the results of:
- `CGPreflightListenEventAccess()`
- `CGPreflightPostEventAccess()`
- `AXIsProcessTrusted()`

Then call `CGRequestListenEventAccess()` if the first returns false.

**Listen-only tap.**
- Create it with `CGEvent.tapCreate(tap: .cgSessionEventTap, place: .headInsertEventTap, options: .listenOnly, eventsOfInterest: mask, callback:, userInfo:)`.
- `mask` covers `flagsChanged`, `keyDown`, `leftMouseDown`, `rightMouseDown`, and `otherMouseDown`.
- Add its run-loop source to the main run loop.
- Log `tap created: yes/no`.

**Detecting Right ⌘.**
- On `flagsChanged` with keycode 54 (`kVK_RightCommand`), Right ⌘ is down when the raw flags include the device bit `NX_DEVICERCMDKEYMASK` (`0x10`). Read it as `event.flags.rawValue & 0x10 != 0`. Otherwise it's up.
- Don't use `.maskCommand` for this, because Left ⌘ also sets it.
- Other modifier keys changing while Right ⌘ is held count as "another key".

**Throwaway gesture logic.** Use the spec timings:
- Hold = 250 ms alone. A `DispatchQueue.main.asyncAfter` timer is fine.
- Double-tap = a second press within 300 ms of the first release.
- In hands-free mode, a double-tap stops.
- Any key or mouse-down while Right ⌘ is down before 250 ms means it's a chord, so do nothing.
- Log `HOLD START`, `HOLD STOP`, `HANDS-FREE START`, `HANDS-FREE STOP`, `CHORD`, and `SINGLE TAP (ignored)`.

**Active tap during any recording.**
- Create a second tap with `options: .defaultTap` for `leftMouseDown`, `leftMouseUp`, `leftMouseDragged`, `rightMouseDown`, `rightMouseUp`, `scrollWheel`, and `keyDown`.
- In the callback:
  - For mouse and scroll events during a **hold** recording: `event.flags.remove(.maskCommand)`, then return the event.
  - For `keyDown` with keycode 53 (Esc) while Right ⌘ is down: log `CANCEL (Esc consumed)` and return `nil`.
  - For `tapDisabledByTimeout` and `tapDisabledByUserInput`: re-enable with `CGEvent.tapEnable(tap:enable:true)` and log it.
- Log `active tap created: yes/no`. It may fail without Accessibility.
- Tear it down when recording stops: `tapEnable(false)`, remove the run-loop source, `CFMachPortInvalidate`.

**Trust watchdog.** While the active tap exists, a 2 s timer checks `AXIsProcessTrusted()`. If it has become false, tear down the active tap immediately and log `ACCESSIBILITY REVOKED — active tap removed`.

### Task 3: Spike B — Accessibility labels at the click point

**Files:**
- Create: `spikes/Sources/FlipbookSpike/AXSpike.swift`
- Modify: `main.swift` (add the `AX spike` item and a `Enable AX in Chrome/Electron` item)
- Modify: `docs/spikes/findings.md` (**Accessibility labels**)

**Interfaces:**
- Consumes: `log(_:)`.
- Produces: nothing reused.

**What to build:**

**Listen-only tap for mouse-downs.** Create it with `CGEvent.tapCreate(tap: .cgSessionEventTap, place: .headInsertEventTap, options: .listenOnly, eventsOfInterest: 1 << CGEventType.leftMouseDown.rawValue, callback:, userInfo:)`, and add its run-loop source to the main run loop. It needs Input Monitoring.

**Label lookup on each left mouse-down.**
- Take the point from `event.location`: global coordinates, top-left origin, in points.
- Call `AXUIElementCopyElementAtPosition(AXUIElementCreateSystemWide(), Float(x), Float(y), &element)` and time it in ms.
- Read `kAXRoleAttribute`, `kAXSubroleAttribute`, `kAXRoleDescriptionAttribute`, `kAXTitleAttribute`, `kAXDescriptionAttribute`, and `kAXHelpAttribute`.
- Read `kAXValueAttribute` **only** when the subrole is not `AXSecureTextField`.
- If both title and description are empty, walk up `kAXParentAttribute` at most 3 levels and read them again.

**Log line.** Log: app name (`NSWorkspace.shared.frontmostApplication?.localizedName`), window title (the app element's `kAXFocusedWindowAttribute` → `kAXTitleAttribute`), role description, best label, and lookup time in ms.

**`Enable AX in Chrome/Electron`.** For each running app, call `AXUIElementCreateApplication(pid)`, then:
- For Google Chrome: set `"AXEnhancedUserInterface" as CFString` to `kCFBooleanTrue`.
- For Electron apps (Cursor, Slack, VS Code): set `"AXManualAccessibility" as CFString` to `kCFBooleanTrue`.
- Log each result code.

- [ ] **Step 2: Manual check (Fayzan).**
  - Click a button, a link, and a text field in Chrome (e.g. any GitHub page), in Safari, in Cursor (a file-tree item and a toolbar button), in Slack (a channel name), in Finder (a file), and in System Settings (a toggle).
  - Do the Chrome, Cursor, and Slack clicks twice: once before and once after `Enable AX in Chrome/Electron`.
  - Note any side effects after enabling. For example, `AXEnhancedUserInterface` is known to make some window animations jerky.

- [ ] **Step 3: Record findings.**
  - A table with the columns: app × label quality (good / generic / none) × needs flag? × typical lookup ms.
  - A decision line for M2: whether Flipbook sets these flags, and when (only while recording).

### Task 4: Spike C — Capture start, idle frames, dirty rects, exclusion

**Files:**
- Create: `spikes/Sources/FlipbookSpike/CaptureSpike.swift`
- Modify: `main.swift` (add the `Capture spike (10 s)` item). At launch, also create a test "pill" `NSPanel` that shows the text `PILL — must not appear in frames`.
- Modify: `docs/spikes/findings.md` (**Capture**)

**Interfaces:**
- Consumes: `log(_:)`.
- Produces: nothing reused. The real capture code arrives in the M2 plan.

**What to build:**

**The pill panel.**
- Create `NSPanel(contentRect:styleMask: [.nonactivatingPanel, .borderless], backing: .buffered, defer: false)` with:
  - `level = .statusBar`
  - `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`
  - `hidesOnDeactivate = false`
- Place it at the bottom center of the main screen and show it. Create it at launch, before any capture filter exists.

**On `Capture spike (10 s)`:**
1. **Shareable content.** `try await SCShareableContent.excludingDesktopWindows(false, onScreenWindowsOnly: true)`. Log how long it took.
2. **Display under the cursor.** Find the `NSScreen` containing `NSEvent.mouseLocation`, then `deviceDescription[NSDeviceDescriptionKey("NSScreenNumber")] as! CGDirectDisplayID`, then the matching `SCDisplay`.
3. **Filter.** `SCContentFilter(display:excludingApplications:exceptingWindows:)`, excluding:
   - this app, matched by bundle id,
   - `com.apple.notificationcenterui`.
4. **Configuration** (`SCStreamConfiguration`):
   - `width`/`height`: the display's pixel size scaled so the long edge is 1920, keeping the aspect ratio
   - `minimumFrameInterval = CMTime(value: 1, timescale: 10)`
   - `pixelFormat = kCVPixelFormatType_32BGRA`
   - `showsCursor = true`
   - `queueDepth = 6`
5. **Start.** Add a `.screen` stream output on a serial queue and call `startCapture()`. Log the time from calling `startCapture()` to the first frame with status `.complete`.
6. **Per frame.** Read `CMSampleBufferGetSampleAttachmentsArray(sampleBuffer, createIfNecessary: false)`, first dictionary. Log:
   - `SCStreamFrameInfo.status` (raw value)
   - the number of `SCStreamFrameInfo.dirtyRects` (each is a `CGRect(dictionaryRepresentation:)`), their total area, and the minimum and maximum of their x/y/width/height (this reveals whether they're in points or output pixels)
   - `SCStreamFrameInfo.contentRect`, `.contentScale`, `.scaleFactor`
7. **Saved frames.** Once per second, save the latest complete frame as a PNG to `~/Desktop/flipbook-spike-frames/<n>.png` (`CIImage` → `CGImage` → ImageIO).
8. **Notification.** At second 3, post a notification via `Process` running `/usr/bin/osascript -e 'display notification "spike" with title "Flipbook"'`.
9. **Stop.** Stop after 10 s and log a summary: complete, idle, and other frame counts, plus the start latency.

- [ ] **Step 1:** Implement. Then `make spike-run`. Grant Screen Recording when asked (relaunch if macOS requires it).

- [ ] **Step 2: Manual check (Fayzan).** Run the capture four times:
  1. With your hands off the Mac. Expect very few complete frames.
  2. While typing a sentence in TextEdit. Expect small dirty rects, including thin caret rects.
  3. While scrolling a long web page. Expect large dirty rects.
  4. On the ultrawide display, to check scaling (2560×1080 → 1920×810).

  After the runs:
  - Open the saved PNGs. The pill and the notification banner must **not** appear.
  - Run `make spike-zip`, AirDrop `build/FlipbookSpike.zip` to the work Mac, unzip it into `~/Applications`, and run `xattr -dr com.apple.quarantine ~/Applications/FlipbookSpike.app`.
  - Repeat runs 1 and 3 on the work Mac (macOS 26).

- [ ] **Step 3: Record findings.**
  - Start latency: 3 runs × 2 Macs.
  - Idle behavior.
  - The dirty-rect coordinate space: "points" or "output pixels", plus the conversion the real Capture module must apply.
  - Pass/fail for excluding the pill and the notification banner.
  - Any macOS 26 differences.
  - Whether a Screen Recording re-prompt appeared.

- [ ] **Step 4: Commit** with the message `spike: capture behavior and exclusion` plus the trailer.

### Task 5: Spike D — Dragging 20 PNGs out of a floating card
